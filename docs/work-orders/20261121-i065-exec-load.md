# 작업 지시: 고정 주소 `ET_EXEC` 실행 파일 로드 (issue #65)

설계: [20261121-i065](../design/20261121-i065-exec-load.md)
브랜치: `i65-exec-load`(main `7f856eb`에서). 작업 위치는 reDMP2 안의 submodule `third_party/repsp`다.

1. `src/module/prx.cpp`: `ProcessPrx`가 `e_type 2`를 받는다(설계 §2: image 기준, base 불일치 오류, 재배치 없음과 `SHT_PRXRELOC` 거부, 절대 entry와 범위 검사, 모듈 정보의 `sh_addr`/`p_paddr` 규약). PRX 경로는 바꾸지 않는다. 필요하면 `ET_EXEC` 처리를 같은 파일 안의 별도 함수로 나눈다.
2. `ParsePrx`의 base·entry·image_end·import/export가 `ET_EXEC`에서 맞는지 확인하고 필요한 곳만 고친다.
3. `include/repsp/module/prx.h`, `include/repsp/runtime/prx_loader.h`의 주석에 `ET_EXEC`를 받는다고 적는다. 시그니처는 그대로.
4. probe: 합성 `ET_EXEC` 픽스처를 코드로 만드는 probe(기존 PRX probe와 같은 방식, 설계 §3의 1·2), CTest `TIMEOUT` 포함.
5. 문서: `ARCHITECTURE.md`의 모듈 로더 설명, `docs/kb/`의 실행 파일 형식 항목(PRX와 `ET_EXEC`의 차이, `p_paddr` 규약; 없으면 만들고 `docs/kb/README.md` 색인), 작업 로그 `docs/work-logs/20261121-i065-exec-load.md`.
6. 검증: 설계 §3. repsp 단독 빌드(Win64 Debug/Release)와 CTest, 그리고 reDMP2 빌드(이 submodule 작업 트리 그대로)로 실제 실행 파일이 로드되는지와 그 다음 어디서 멈추는지 확인한다. 소비자 쪽 결과는 보고에만 적고 reDMP2 파일은 바꾸지 않는다.

지킬 것: 타이틀 이름·타이틀 주소를 코드·probe·문서에 쓰지 않는다(`0x08804000`은 PSP 사용자 메모리 시작 주소라는 일반 사실로만). PPSSPP(GPL) 코드는 보지 않는다. 게임 유래 데이터는 커밋하지 않는다. 작업 단위마다 커밋, 제목 끝에 `(#65)`. push·PR·merge·tag 금지. Linux에서도 빌드되도록 GCC 경고(`-Wall -Wextra -Wpedantic -Werror`)를 미리 살핀다.

완료 기준: 설계 §3의 1~4.
