# 설계: PRX 로더 — 재배치 가능한 PRX를 기준 주소에 올리기 (issue #3)

## 1. 요구사항

* 재배치 가능한 PSP 사용자 모드 PRX(평문 ELF, `e_type` `0xFFA0`)를 읽어, 호출자가 정한 기준 주소에 `GuestMemory`로 올리고 재배치를 적용한다. 첫 소비자 reDMP1은 실제 펌웨어처럼 모듈을 `0x08804000`에 올린다([reDMP1 issue #3](https://github.com/reexec/reDMP1/issues/3)).
* 모듈 정보(`sceModuleInfo`), import 표(라이브러리 이름, NID, stub 주소), export 표를 읽어 돌려준다. HLE 연결(stub → NID)은 이 정보로 소비자나 이후의 ModuleMgr HLE가 한다.
* lifter에 중립이다. 코드를 실행하지 않고, 생성 코드나 lifter를 모른다.
* 범위 밖: `~PSP` 복호화, 압축 재배치 형식(`0x700000A1`; 만나면 "지원하지 않음"으로 거부), ISO9660, 모듈 시작(스레드·스택은 커널 HLE task).

## 2. PRX 재배치 형식

출처: [PSP Developer Wiki — PRX](https://www.psdevwiki.com/psp/), uOFW loadcore 문서(**추정**). 아래 "측정"은 reDMP1의 원본 실행 파일에서 잰 값이다([reDMP1 analysis/executable.md](https://github.com/reexec/reDMP1/blob/main/docs/analysis/executable.md), issue #3에서 갱신).

* 재배치 섹션의 형식은 `SHT_PRXRELOC`(`0x700000A0`)이고, 항목은 `Elf32_Rel { r_offset, r_info }`다.
* `r_info`의 비트 0~7은 유형, 8~15는 **오프셋 기준 세그먼트**(`ofsbase`), 16~23은 **주소 기준 세그먼트**(`addrbase`)다.
* 고칠 위치: `base + seg[ofsbase].vaddr + r_offset`.
* 더할 값: `base + seg[addrbase].vaddr`. 저장된 값은 `addrbase` 세그먼트 시작에서의 상대값이다. 측정: `addrbase` 1인 `R_MIPS_32` 265개 중 264개, `HI16/LO16` 2,845쌍 중 1,971쌍의 값이 세그먼트 1의 시작(`0xFB090`)보다 작아 절대 주소일 수 없다. 나머지는 상대값이 `0xFB090` 이상인 경우로 설명된다.

| 유형 | 이름 | 적용 |
|---|---|---|
| 2 | `R_MIPS_32` | `word += S` |
| 4 | `R_MIPS_26` | `target = ((word & 0x03FFFFFF) << 2) + S`; `word = (word & 0xFC000000) \| ((target >> 2) & 0x03FFFFFF)` |
| 5 | `R_MIPS_HI16` | 짝인 `LO16`과 함께 `addend = (hi << 16) + (int16)lo`, `value = addend + S`, `hi = (value + 0x8000) >> 16` |
| 6 | `R_MIPS_LO16` | `lo = (lo + S) & 0xFFFF` (짝인 `HI16`이 carry를 맡는다) |

`S = base + seg[addrbase].vaddr`.

* `HI16`은 바로 뒤의 `LO16`과 짝을 이룬다. 측정에서 `LO16`(6,311개)이 `HI16`(5,859개)보다 많으므로, `HI16` 없이 오는 `LO16`이 있다. 표준 MIPS 규칙처럼 `HI16`은 다음 `LO16`의 값으로 addend를 만들고, 그 뒤 홀로 오는 `LO16`은 자기 값만 고친다(**추정**, probe와 reDMP1의 교차 검사로 확인).
* 측정된 유형은 2, 4, 5, 6뿐이다. 다른 유형은 오류로 보고하고 로드를 거부한다.

## 3. 공개 계약

`include/repsp/module/prx.h`(C++), 기준안:

```cpp
namespace repsp::module
{
struct PrxSegment { uint32_t vaddr, file_offset, file_size, mem_size; };
struct PrxImport { std::string library; uint32_t nid; uint32_t stub_address; };  // stub address after relocation
struct PrxExport { std::string library; uint32_t nid; uint32_t address; };
struct PrxModuleInfo { std::string name; uint16_t attribute; uint8_t version[2]; uint32_t gp; };
struct LoadedPrx
{
    uint32_t base;            // where segment 0 was placed
    uint32_t entry;           // relocated e_entry
    uint32_t gp;              // relocated $gp
    uint32_t image_end;       // base + highest segment end (bss included)
    PrxModuleInfo info;
    std::vector<PrxSegment> segments;   // link-time values
    std::vector<PrxImport> imports;
    std::vector<PrxExport> exports;
    size_t relocations_applied;
};
// Parse only (no memory writes): validates the ELF and reports what Load would do.
std::optional<LoadedPrx> ParsePrx(std::span<const uint8_t> file, uint32_t base, std::string* error);
// Copy segments to guest memory at base, zero bss, apply relocations.
std::optional<LoadedPrx> LoadPrx(std::span<const uint8_t> file, uint32_t base,
                                 runtime::GuestMemory& memory, std::string* error);
// The relocated image as bytes (segments laid out from base), for cross-checks.
std::optional<std::vector<uint8_t>> RelocateToBuffer(std::span<const uint8_t> file, uint32_t base, std::string* error);
}
```

* 이름과 형태는 기준안이다. 바꾸면 작업 로그와 `ARCHITECTURE.md`의 소비자 계약 절에 적는다.
* `RelocateToBuffer`는 소비자가 다른 구현(예: lifter의 재배치)과 바이트 단위로 비교할 수 있게 한다. 두 구현이 독립으로 같은 결과를 내는 것이 재배치 규칙의 검증이다.
* 레이어: `repsp_module`은 `GuestMemory`를 쓰므로 `LoadPrx`는 runtime에 의존한다. 그러나 현재 레이어는 `module → platform`, `runtime → module`이다. 그래서 `ParsePrx`와 `RelocateToBuffer`는 `repsp_module`에 두고, `GuestMemory`에 쓰는 `LoadPrx`는 `repsp_runtime`의 `include/repsp/runtime/prx_loader.h`에 둔다(`RelocateToBuffer`의 결과를 `WriteBlock`으로 복사).
* 기준 주소의 기본값은 계약에 두지 않는다. 호출자가 정한다(이후 SysMem HLE가 파티션에서 할당하게 되면 그 값).

## 4. import·export 표

* 모듈 정보의 `stub_top..stub_end`는 `sceLibraryStubTable` 배열이다(라이브러리 이름 포인터, 버전, 속성, 항목 크기, 변수 수, 함수 수, NID 표 포인터, stub 표 포인터; **추정**, psdevwiki). 포인터들은 재배치된 이미지에서 읽는다.
* 함수 stub 하나는 8바이트다. 측정: stub 영역은 1,272바이트로 159개 함수 stub에 해당한다(reDMP1 issue #1의 `allegrexrecomp info`).
* 변수 import는 이번에 읽기만 하고 보고한다(측정된 모듈에 있는지부터 작업 로그에 적는다).

## 5. 검증

1. 손으로 만든 합성 PRX(세그먼트 2개, 네 유형, `addrbase` 0과 1, carry가 생기는 `HI16/LO16` 쌍, 홀로 오는 `LO16`, stub 표 1개)를 probe 안에서 바이트로 조립하고 `ParsePrx`·`RelocateToBuffer`·`LoadPrx` 결과를 검사하는 `prx_probe`.
2. 잘못된 입력(짧은 파일, ELF 아님, 알 수 없는 재배치 유형, 압축 재배치 섹션, 세그먼트 범위 밖 `r_offset`)의 거부.
3. Win64 Debug/Release, Linux x64 Debug/Release 빌드와 CTest.
4. 실제 모듈로의 확인은 reDMP1 issue #3이 한다(교차 검사).
5. kb: `docs/kb/prx-format.md`(모듈 정보, stub 표, 재배치; 확인 상태와 출처), 색인 갱신.

# Design: PRX loader — placing a relocatable PRX at a base address (issue #3)

## 1. Requirements

* Read a relocatable PSP user-mode PRX (plain ELF, `e_type` `0xFFA0`), place it through `GuestMemory` at a base address the caller chooses, and apply its relocations. The first consumer, reDMP1, places its module at `0x08804000` as the real firmware does ([reDMP1 issue #3](https://github.com/reexec/reDMP1/issues/3)).
* Return the module info (`sceModuleInfo`), the import table (library name, NID, stub address) and the export table. HLE binding (stub → NID) is done from this by the consumer or a later ModuleMgr HLE.
* Lifter-neutral: it runs no code and knows no generated code or lifter.
* Out of scope: `~PSP` decryption, the compressed relocation format (`0x700000A1`, rejected as unsupported when met), ISO9660, starting a module (threads and stacks are the kernel HLE task).

## 2. PRX relocation format

Sources: [PSP Developer Wiki — PRX](https://www.psdevwiki.com/psp/), the uOFW loadcore documentation (**inferred**). "Measured" values below come from reDMP1's original executable ([reDMP1 analysis/executable.md](https://github.com/reexec/reDMP1/blob/main/docs/analysis/executable.md), updated in its issue #3).

* Relocation sections are `SHT_PRXRELOC` (`0x700000A0`) with `Elf32_Rel { r_offset, r_info }` entries.
* `r_info` bits 0-7 are the type, 8-15 the **offset-base segment** (`ofsbase`), 16-23 the **address-base segment** (`addrbase`).
* The patched location is `base + seg[ofsbase].vaddr + r_offset`.
* The value added is `S = base + seg[addrbase].vaddr`; the stored value is relative to the start of the `addrbase` segment. Measured: of the `R_MIPS_32` entries with `addrbase` 1, 264 of 265, and of the `HI16/LO16` pairs, 1,971 of 2,845, hold values below segment 1's start (`0xFB090`) and cannot be absolute; the rest are relative values at or above `0xFB090`.
* The table above gives each type's rule. A `HI16` pairs with the `LO16` right after it; since the measured module has more `LO16` (6,311) than `HI16` (5,859) entries, some `LO16` come alone: as in the standard MIPS rules the `HI16` forms its addend with the next `LO16`'s value, and a later lone `LO16` fixes only itself (**inferred**, checked by the probe and reDMP1's cross-check). Only types 2, 4, 5 and 6 were measured; any other type is reported as an error and the load is refused.

## 3. Public contract

`include/repsp/module/prx.h` (C++), baseline as above. Names and shapes are the baseline; changes go to the work log and the consumer-contract section of `ARCHITECTURE.md`. `RelocateToBuffer` lets a consumer compare byte for byte with another implementation (for example the lifter's relocation); two independent implementations agreeing is the check of the relocation rules. Layering: `repsp_module` sits below `repsp_runtime`, so `ParsePrx` and `RelocateToBuffer` live in `repsp_module`, and `LoadPrx`, which writes `GuestMemory`, lives in `repsp_runtime` as `include/repsp/runtime/prx_loader.h` (copying `RelocateToBuffer`'s result with `WriteBlock`). The contract has no default base; the caller chooses it (later, the value SysMem HLE allocates from a partition).

## 4. Import and export tables

* The module info's `stub_top..stub_end` is an array of `sceLibraryStubTable` (library-name pointer, version, attribute, entry size, variable count, function count, NID-table pointer, stub-table pointer; **inferred**, psdevwiki), whose pointers are read from the relocated image.
* A function stub is 8 bytes; measured: the stub area is 1,272 bytes, 159 function stubs (reDMP1 issue #1, `allegrexrecomp info`).
* Variable imports are read and reported only this time (the work log first records whether the measured module has any).

## 5. Verification

1. `prx_probe`: a hand-made synthetic PRX assembled in bytes inside the probe (two segments, the four types, `addrbase` 0 and 1, a `HI16/LO16` pair with carry, a lone `LO16`, one stub table), checked through `ParsePrx`, `RelocateToBuffer` and `LoadPrx`.
2. Rejection of bad input (short file, not ELF, unknown relocation type, compressed relocation section, `r_offset` outside its segment).
3. Win64 Debug/Release and Linux x64 Debug/Release builds and CTest.
4. The check against a real module is reDMP1 issue #3's cross-check.
5. kb: `docs/kb/prx-format.md` (module info, stub tables, relocations, with confirmation status and sources), index updated.
