# 설계: 메뉴 진입을 위한 수정 — 씬 정리 중의 결함, sprite 가장자리 texel (issue #17)

## 1. 요구사항

* 소비자([reDMP1 issue #18](https://github.com/reexec/reDMP1/issues/18))가 타이틀 화면을 떠날 때 게스트 assertion으로 끝난다. 원인 분석은 소비자 쪽 설계가 정한 방법으로 하고, 원인이 repsp(HLE, 스케줄러, 렌더러)에 있으면 여기서 고친다.
* 소프트웨어 래스터라이저가 일부 sprite의 가장자리에 텍스처의 색 키 색(마젠타)으로 된 1픽셀 선을 그린다. 원인을 확인하고 고친다.

## 2. 진단 기능

* 원인 분석에 필요한, 타이틀에 묶이지 않는 추적 수단을 환경 변수로 켜는 진단 기능으로 더할 수 있다(예: 지정한 게스트 주소 범위에 대한 HLE의 쓰기 기록, 스레드 전환 기록, 지정한 NID의 인자·반환값 기록). 꺼져 있을 때 비용이 없어야 하고, `docs/kb/` 또는 `ARCHITECTURE.md`에 적는다.
* 타이틀의 주소나 이름을 아는 코드는 넣지 않는다.

## 3. 수정 원칙

* HLE 반환값·부작용의 차이는 공개 자료(PSPSDK 헤더, psdevwiki, uOFW)로 실제 동작을 확인한 뒤 고치고, KB의 해당 항목을 **확인됨** 또는 **추정**으로 갱신한다.
* 스케줄러의 의미(선점 시점, 깨우는 순서, 콜백 시점)를 바꿔야 한다면 고치지 말고, 지금 동작과 실제 동작의 차이와 근거를 소비자 작업 로그의 질문으로 올린다.
* 모든 수정에는 그 결함을 다시 잡는 probe를 더한다.

## 4. sprite 가장자리 texel

* 조사할 것: sprite의 텍스처 좌표 보간(픽셀 중심 표본화와 끝 좌표의 처리), 텍스처 필터(nearest일 때의 반올림), 래핑·클램프 모드, 색 키(color test)와 알파 테스트의 적용 여부와 순서, 텍스처 크기와 실제 그림 영역의 차이.
* 원인을 GE 명령 상태와 대조해 확정한 뒤 고친다. 특정 색을 버리는 식의 임시 보정은 넣지 않는다.
* `ge_probe`에 그 경우를 재현하는 합성 리스트를 더한다(가장자리 texel이 인접 texel의 색을 가져오지 않음).

## 5. 이번 task의 검증

1. 더한 수정마다 probe가 있고 통과한다.
2. `ge_probe`의 가장자리 texel 경우가 통과한다.
3. Win64 Debug/Release, Linux x64 Debug/Release 빌드와 CTest. probe는 실제 게임 데이터를 쓰지 않는다.

# Design: fixes for entering the menu — a fault during scene teardown, sprite edge texels (issue #17)

## 1. Requirements

The consumer ([reDMP1 issue #18](https://github.com/reexec/reDMP1/issues/18)) ends in a guest assertion when it leaves its title screen. The cause is analyzed by the method in the consumer's design; if it lies in repsp (HLE, scheduler, renderer) it is fixed here. The software rasterizer draws one-pixel lines in the texture's key colour (magenta) along some sprite edges; confirm the cause and fix it.

## 2. Diagnostics

Tracing aids needed for the analysis that are not tied to a title may be added as diagnostics switched on by environment variables (for example a log of HLE writes into a given guest address range, of thread switches, or of the arguments and return values of chosen NIDs). They cost nothing when off and are described in `docs/kb/` or `ARCHITECTURE.md`. No code that knows a title's addresses or names.

## 3. Rules for fixes

A difference in an HLE return value or side effect is fixed after the real behaviour is confirmed from public sources (PSPSDK headers, psdevwiki, uOFW), and the knowledge base entry is updated as **confirmed** or **assumed**. If scheduler semantics (when preemption happens, wake order, callback timing) would have to change, it is not fixed: the difference between present and real behaviour, with evidence, is raised as a question in the consumer's work log. Every fix comes with a probe that catches the defect again.

## 4. Sprite edge texels

To examine: texture coordinate interpolation for sprites (sampling at pixel centres and the handling of the end coordinate), the texture filter (rounding under nearest), wrap and clamp modes, whether and in what order the colour test and alpha test apply, and the difference between the texture size and the area actually holding the picture. The cause is confirmed against the GE command state before fixing; no ad hoc correction such as discarding a particular colour. `ge_probe` gains a synthetic list reproducing the case (an edge texel does not pick up its neighbour's colour).

## 5. Verification for this task

1. Every fix has a probe, and it passes.
2. The edge texel case in `ge_probe` passes.
3. Win64 Debug/Release and Linux x64 Debug/Release builds and CTest; probes use no real game data.
