# 설계: UMD 교체 모델과 링크 디스크 경로 HLE (issue #79, #80)

소비자 요구: [reexec/reDMP2#23](https://github.com/reexec/reDMP2/issues/23)(링크 디스크). 소비자 분석: reDMP2 `docs/analysis/link-disc.md`.

두 issue를 한 브랜치에서 진행한다.
* #79: UMD 교체 모델
* #80: 교체 전에 불리는 HLE

## 1. 배경 (소비자 분석, 확인됨)

* 소비자는 교체 대기 중 매 프레임 `sceUmdGetDriveStat() & 0x20`(READY)만 본다.
* 15초 넘게 준비가 안 되면 `sceUmdCheckMedium()`을 부르고, 0이면 디스크가 없다고 본다.
* 교체 허용 전에는 `sceImposeSetUMDPopup(0)` → `sceUmdReplacePermit()`, 맞는 디스크를 확인한 뒤에는 `sceUmdReplaceProhibit()` → `sceImposeSetUMDPopup(1)`을 부른다.
* 교체 전에 열린 아카이브를 스스로 닫는다. 교체한 뒤 새 디스크의 `PARAM.SFO`와 `USRDIR/all.mp`·`all2.mp`를 연다.
* 다른 경로(파일 입출력 재시도)는 `sceUmdWaitDriveStat(0x20)`, `sceUmdWaitDriveStatWithTimer(0x20, 10 s)`로 기다린다.
* 교체 전에 다음을 부른다.
  * 세이브 유틸리티 모드 12/13/15/17/19/22
  * `sceIoDevctl("ms0:", 0x02425818, ...)`
  * `sceKernelVolatileMemTryLock`/`Unlock`

## 2. #79 UMD 교체 모델

### 2.1 상태

* 드라이브 상태 비트는 PSPSDK `pspumd.h`의 `PSP_UMD_NOT_PRESENT`(0x01), `PRESENT`(0x02), `CHANGED`(0x04), `INITING`(0x08), `INITED`(0x10), `READY`(0x20)를 따른다.
  * 디스크가 있고 준비됨: 지금 값 `0x32`(`PRESENT|INITED|READY`)를 유지한다.
  * 꺼냄: `NOT_PRESENT`(`0x01`)만 켠다.
  * 넣은 직후: `PRESENT|CHANGED`(준비 아님)를 거친다.
  * 그 뒤 지정한 시간(기본 짧은 값, 예: 0.5 s) 뒤에 준비 상태(`0x32`)가 된다. 게임이 "준비 안 됨 → 준비"를 볼 수 있게 하려는 것이다. 정확한 실기 시간은 출처가 없으므로 설정값으로 두고 문서에 적는다.
* `ReplacePermit`/`Prohibit`는 "교체 허용" 플래그다. 시작값은 금지다(실기에서 게임 실행 중 UMD 교체는 허용될 때만 의미가 있다).

### 2.2 HLE

* `sceUmdReplacePermit`, `sceUmdReplaceProhibit`: 플래그를 바꾸고 0을 돌려준다.
* `sceUmdCheckMedium`: 디스크가 있으면 0이 아닌 값, 없으면 0. 반환값의 정확한 값은 출처가 있는 것을 쓴다. 없으면 1/0으로 두고 근거를 적는다.
* `sceUmdGetDriveStat`: 현재 상태를 돌려준다.
* `sceUmdWaitDriveStat*`: 요청한 비트가 켜질 때까지 기다린다. 상태가 바뀌면 깨운다. timeout은 지금처럼 지킨다.
* `sceUmdActivate`/`Deactivate`: 지금 동작을 유지한다.

### 2.3 호스트 API (`include/repsp/hle/umd.h` 등)

* 다음을 둔다:
  * `IsReplacePermitted()`
  * `GetDriveStat()`
  * `EjectDisc()`
  * `InsertDisc(const std::filesystem::path& disc_root)`
* `EjectDisc`는 `disc0:`/`umd0:`를 마운트 해제한다.
* `InsertDisc`는 그 폴더로 다시 마운트하고 상태 전이를 시작한다.
* 허용되지 않은 때의 호출은 거부하고 이유를 돌려준다. 실기에서는 물리적으로 언제든 꺼낼 수 있지만, 호스트 UI가 게임의 의도를 따르게 하려는 것이다.
* 게스트 스레드와 호스트(UI) 스레드에서 함께 불리므로 동기화한다.
* 꺼낸 동안 `disc0:` 열기·읽기는 실패한다. 오류 코드는 출처가 있는 것을 쓴다. 이미 열린 핸들은 소비자가 교체 전에 닫으므로 특별한 처리를 하지 않는다. 다만 꺼낸 뒤 그 핸들로 읽으면 실패하게 한다.

## 3. #80 링크 디스크 경로 HLE

* **세이브 유틸리티 모드** 12(FILES), 13(MAKEDATASECURE), 15(READDATASECURE), 17(WRITEDATASECURE), 19(ERASESECURE), 22(GETSIZE):
  * 기존 0..8의 저장 위치·구조체 처리와 같은 방식으로 구현한다.
  * "secure"는 실기에서 게임 키로 암호화된 파일이다. 여기서는 암호화하지 않고 평문 파일로 저장한다. 실기 세이브와의 호환은 목표가 아니다. 이를 `ARCHITECTURE.md`에 적는다.
  * 구조체 필드와 결과 코드는 PSPSDK와 공개 문서를 출처로 쓴다.
* **`sceIoDevctl`**: `ms0:`의 명령 `0x02425818`(여유 공간 조회)을 구현한다. 호스트 디스크의 실제 여유 공간을 PSP 형식(클러스터 수·섹터 크기 등)으로 돌려준다. 너무 크면 PSP가 다룰 수 있는 범위로 자른다. 다른 명령은 미구현으로 보고한다.
* **`sceKernelVolatileMemTryLock`/`Unlock`**: 휘발성 메모리(`0x08400000`, 4 MiB)의 잠금이다. 잠그면 주소와 크기를 돌려주고, 이미 잠겨 있으면 오류를 돌려준다. 같은 묶음의 `sceKernelVolatileMemLock`은 불릴 때 구현한다.

## 4. 검증

1. probe:
   * 상태 전이(꺼냄 → 넣음 → 준비)
   * `WaitDriveStat` 깨우기와 timeout
   * 허용 플래그
   * 꺼낸 동안 `disc0:` 실패, 넣은 뒤 새 폴더 읽기
   * 세이브 모드 6종(쓰기 → 크기 → 읽기 → 지우기)
   * `sceIoDevctl` 여유 공간
   * 휘발성 메모리 잠금·해제·이중 잠금
2. `ARCHITECTURE.md`에 호스트 API와 secure 세이브 처리를 적는다.
3. CTest 전부 통과. Win64 Debug/Release 경고 0. Linux는 CI.
4. 소비자 측정(reDMP2 #23 3단계와 함께): 링크 디스크가 교체 대기 화면까지 가고, DMP1을 넣으면 인식한다.

# Design: UMD swap model and link-disc path HLE (issues #79, #80)

Consumer need: [reexec/reDMP2#23](https://github.com/reexec/reDMP2/issues/23) (link disc). Consumer analysis: reDMP2 `docs/analysis/link-disc.md`.

Both issues are done on one branch:
* #79: the UMD swap model
* #80: the HLE called before the swap

## 1. Background (consumer analysis, confirmed)

* While waiting for the swap, the consumer checks only `sceUmdGetDriveStat() & 0x20` (READY) every frame.
* After more than 15 s without READY it calls `sceUmdCheckMedium()`, and 0 means no disc.
* Before permitting replacement it calls `sceImposeSetUMDPopup(0)` → `sceUmdReplacePermit()`. After confirming the right disc it calls `sceUmdReplaceProhibit()` → `sceImposeSetUMDPopup(1)`.
* It closes its open archives itself before the swap. After the swap it opens the new disc's `PARAM.SFO` and `USRDIR/all.mp` and `all2.mp`.
* Another path (file I/O retry) waits with `sceUmdWaitDriveStat(0x20)` and `sceUmdWaitDriveStatWithTimer(0x20, 10 s)`.
* Before the swap it calls:
  * savedata utility modes 12/13/15/17/19/22
  * `sceIoDevctl("ms0:", 0x02425818, ...)`
  * `sceKernelVolatileMemTryLock`/`Unlock`

## 2. #79 UMD swap model

### 2.1 State

* Drive state bits follow PSPSDK `pspumd.h`: `PSP_UMD_NOT_PRESENT` (0x01), `PRESENT` (0x02), `CHANGED` (0x04), `INITING` (0x08), `INITED` (0x10), `READY` (0x20).
  * Disc present and ready: keep today's value `0x32` (`PRESENT|INITED|READY`).
  * Ejected: only `NOT_PRESENT` (`0x01`).
  * Just inserted: `PRESENT|CHANGED` (not ready).
  * After a set delay (short by default, e.g. 0.5 s) it becomes ready (`0x32`), so a game sees "not ready → ready". The hardware timing has no source, so it is a setting and is documented.
* `ReplacePermit`/`Prohibit` set a "replacement permitted" flag, starting as prohibited (on hardware, swapping during a game only matters when it is permitted).

### 2.2 HLE

* `sceUmdReplacePermit`, `sceUmdReplaceProhibit`: change the flag and return 0.
* `sceUmdCheckMedium`: nonzero with a disc present, 0 without. Use a sourced exact value; without one, use 1/0 and note the basis.
* `sceUmdGetDriveStat`: returns the current state.
* `sceUmdWaitDriveStat*`: wait until the requested bits are set, woken on state changes, with timeouts honoured as today.
* `sceUmdActivate`/`Deactivate`: keep today's behaviour.

### 2.3 Host API (`include/repsp/hle/umd.h` or similar)

* Provide:
  * `IsReplacePermitted()`
  * `GetDriveStat()`
  * `EjectDisc()`
  * `InsertDisc(const std::filesystem::path& disc_root)`
* `EjectDisc` unmounts `disc0:`/`umd0:`.
* `InsertDisc` remounts them to that folder and starts the state transition.
* Calls while replacement is not permitted are refused with a reason. Hardware allows a physical eject at any time, but the host UI should follow the game's intent.
* Called from both guest threads and the host (UI) thread, so synchronized.
* While ejected, opening and reading `disc0:` fail, with sourced error codes. Handles already open need no special treatment, since the consumer closes them before swapping, but reads through them after an eject fail.

## 3. #80 Link-disc path HLE

* **Savedata utility modes** 12 (FILES), 13 (MAKEDATASECURE), 15 (READDATASECURE), 17 (WRITEDATASECURE), 19 (ERASESECURE), 22 (GETSIZE):
  * Implemented in the same way as the existing 0..8, with the same storage location and structure handling.
  * On hardware, "secure" files are encrypted with the game key. Here they are stored as plain files, without encryption; compatibility with hardware saves is not a goal. This is documented in `ARCHITECTURE.md`.
  * Structure fields and result codes are sourced from PSPSDK and public documents.
* **`sceIoDevctl`**: the `ms0:` command `0x02425818` (free space). It returns the host disk's actual free space in PSP form (cluster count, sector size, ...), clamped to a range the PSP can handle. Other commands are reported as unimplemented.
* **`sceKernelVolatileMemTryLock`/`Unlock`**: a lock on volatile memory (`0x08400000`, 4 MiB). Locking returns its address and size; if already locked it returns an error. `sceKernelVolatileMemLock` in the same family is implemented when called.

## 4. Verification

1. Probes:
   * state transitions (eject → insert → ready)
   * `WaitDriveStat` wake-ups and timeouts
   * the permit flag
   * `disc0:` failing while ejected, and reading the new folder after insertion
   * the six savedata modes (write → size → read → erase)
   * `sceIoDevctl` free space
   * volatile memory lock, unlock and double lock
2. `ARCHITECTURE.md` documents the host API and the secure savedata handling.
3. All CTest pass; Win64 Debug/Release with zero warnings; Linux in CI.
4. Consumer measurement (together with reDMP2 #23 phase 3): link disc reaches the swap-wait screen, and inserting DMP1 is recognized.
