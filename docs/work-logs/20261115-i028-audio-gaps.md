## 1. 측정 결과 요약 및 가설 확정

### 1.1. 가설 H1 (GE 리스트 실행 중 선점 불가) 확정

* **수정 전 계측**: `REPSP_SCHED_STATS=1`로 측정 시 소프트웨어(SW) 렌더러에서 단일 GE 리스트 실행 시간이 평균 ~7.5–8.4 ms, 최대 32–44 ms에 달했으며, 오디오 스레드 기상 지연 `>= 10 ms`가 641–697회(`avg = 5772–7100 us`), OpenGL(GL)에서도 228–235회(`avg = 2592–2962 us`) 발생했습니다.
* **수정 후 계측 (`GeInterpreter` 선점 지점 + `DrawPrim` 분할 + 재진입 방어)**:
  * 오디오 스레드 `>= 10 ms` 기상 지연이 SW에서 641–697회 → 14–52회로, GL에서 228–235회 → 3회로 감소했습니다.

### 1.2. 가설 H2 (호스트 오디오 장치 pull 단위와 게스트 큐 깊이 불일치) 확정

* **수정 전 계측**: Windows WASAPI 장치의 pull 크기는 `[441..441]` 프레임(10 ms)으로 고정되어 있었으며, 게스트 SAS 채널(`ch2`) 이중 버퍼(512프레임 = 11.6 ms)와 정렬이 맞지 않아 `partial_underruns`가 1145–1602회 발생했습니다.
* **수정 후 계측 (`ClockThreadMain` 128프레임 믹싱 + 20 ms 호스트 중간 버퍼)**:
  * 모든 실행 모드(GL 창, GL 헤드리스, SW 창, SW 헤드리스)에서 `partial_underruns`가 `1145–1602`회 → `0`회로 완전히 제거되었습니다.

## 2. 구현 내용

1. **스케줄러 기상 지연 계측 (`include/repsp/runtime/scheduler.h`, `src/runtime/scheduler.cpp`)**:
   * `REPSP_SCHED_STATS=1` 또는 `SetWakeLatencyProfiling(true)` 시 기상 원인(`Delay`, `Audio`, `Custom` 등) 및 우선순위 구간(`p16-31`, `p32-63`)별 대기→실행 지연을 계측하고 `FormatWakeLatencyStats()`로 보고합니다. 비활성 시 오버헤드가 없습니다.
2. **GE 리스트 실행 시간 계측 및 선점 양보 (`include/repsp/gpu/ge_interpreter.h`, `src/gpu/ge_interpreter.cpp`, `src/hle/ge/hle_ge.cpp`)**:
   * `GeStats`에 리스트 실행 시간 히스토그램(`list_time_*`) 및 `yield_points` 카운터를 추가했습니다.
   * `GeInterpreter::SetYieldCallback`을 `hle_ge`에서 `Scheduler::YieldIfPreempted()`와 연결하고, `RunList` 경과 시간(>= 1000 us 이후 256명령 또는 2 프리미티브/64 정점마다) 및 대형 비스트립/비팬 `DrawPrim`(`kPrimTriangles` 24정점, `kPrimSprites`/`kPrimLines` 16정점 분할)에서 선점 지점을 제공합니다.
   * 선점 도중 다른 스레드의 `sceGe*` 재진입으로 리스트 큐가 꼬이지 않도록 `hle_ge.cpp`의 `DrainQueue`/`Enqueue`/`UpdateStallAddr`/`Continue`/`GetListState`를 `running_list_` 상태로 보호했습니다.
3. **오디오 실측 지표 및 호스트 중간 버퍼 (`include/repsp/hle/audio.h`, `src/hle/audio/hle_audio.cpp`)**:

   * `AudioHleConfig::target_latency_ms`(기본 `20`, `REPSP_AUDIO_LATENCY_MS` 재정의 가능) 및 `Register(const AudioHleConfig&)`를 추가하고, `ClockThreadMain`이 `128`-프레임 고정 단위로 게스트 채널을 믹싱해 중간 버퍼(`882`프레임)를 유지하도록 했습니다.
4. **회귀 테스트 (`tools/ge_probe/main.cpp`, `tools/audio_probe/main.cpp`)**:
   * `ge_probe` Check 13: 긴 GE 리스트 실행 중 외부 스레드 기상으로 고우선순위 스레드가 선점 실행되고, 그 스레드가 `sceGeListEnQueue`를 호출해도 큐 순서가 유지됨을 검증합니다.

5. **문서 (`ARCHITECTURE.md`, `docs/kb/audio.md`)**:
   * `REPSP_SCHED_STATS`, `GeInterpreter` 선점·재진입 보호, `AudioHleConfig::target_latency_ms` 및 `128`-프레임 중간 버퍼 구조를 반영했습니다.

# Work Log: Audio Gaps and Slowdown Fix (repsp issue #28)

* Date: 2026-11-15
* Target repository / branch: `third_party/repsp` (`i028-audio-gaps`)
* Related design: [20261115-i028-audio-gaps.md](../design/20261115-i028-audio-gaps.md)
* Related work order: [20261115-i028-audio-gaps.md](../work-orders/20261115-i028-audio-gaps.md)

## 1. Measurements and Hypothesis Confirmation

* **H1 (No preemption during GE list execution)**: Before the fix, single software-rasterizer GE lists ran up to 32–44 ms synchronously (`avg 7.5–8.4 ms`), causing `641–697` audio thread wakeups `>= 10 ms` (`228–235` on OpenGL). Adding yield points in `GeInterpreter::RunList` and chunking large non-strip/non-fan `DrawPrim` calls reduced audio wakeups `>= 10 ms` to `14–52` (SW) and `3` (GL).
* **H2 (Host audio pull size vs. guest double-buffer alignment)**: Before the fix, Windows WASAPI pulled `441`-frame (`10 ms`) blocks against `2 * 256 = 512`-frame (`11.6 ms`) guest SAS buffers, causing `1,145–1,602` partial underruns. Adding a `128`-frame steady-clock mixing thread feeding a `20 ms` (`882`-frame) host-side intermediate buffer eliminated all partial underruns (`0` across all runs).

## 2. Implementation Summary

* `Scheduler` (`scheduler.h`, `scheduler.cpp`): Opt-in wake latency profiling via `REPSP_SCHED_STATS=1` / `SetWakeLatencyProfiling(true)` with zero overhead when disabled.
* `repsp_gpu` / `repsp_hle_ge` (`ge_interpreter.h/.cpp`, `hle_ge.cpp`): Added `GeStats` list execution time histogram and `yield_points`, connected `GeYieldCallback` to `Scheduler::YieldIfPreempted()`, chunked large `kPrimTriangles`/`kPrimSprites`/`kPrimLines` `DrawPrim` calls, and guarded `hle_ge` queue state with `running_list_` against re-entrant `sceGe*` calls during preemption.
* `repsp_hle_audio` (`audio.h`, `hle_audio.cpp`): Separated `empty_underruns`, `partial_underruns`, `host_underruns`, pull size histogram, and buffer depth stats with a 100 ms idle cutoff; added `AudioHleConfig::target_latency_ms` (default `20`, `REPSP_AUDIO_LATENCY_MS` override) and `ClockThreadMain` mixing in fixed `128`-frame units into the intermediate buffer.
* Probes (`ge_probe` Check 13, `audio_probe` Checks 5–6): Verified preemption + re-entry ordering on GE lists and `441`-frame unaligned host pulls with `256`-frame guest producers (`0` partial/host underruns on time, `host_underruns > 0` when producer stalls).
* Docs (`ARCHITECTURE.md`, `docs/kb/audio.md`): Updated scheduler stats, GE preemption/re-entry, and intermediate audio buffer contracts.
