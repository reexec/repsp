# 작업 로그: 게스트 스레드 호스트 스택 예약 및 최고 사용량 보고 (repsp #32)

## 요약

`/STACK` 링커 우회 없이 게스트 스레드가 충분한 호스트 스택을 확보할 수 있도록 플랫폼 스레드 생성 계층과 스케줄러를 확장하고, 스레드별 OS 호스트 스택 최고 사용량을 측정·보고하는 진단 기능을 추가했습니다.

## 변경 내용

1. **플랫폼 스레드 스택 예약 및 조회 (`include/repsp/platform/host_thread.h`, `src/platform/win32/host_thread_win32.cpp`, `src/platform/linux/host_thread_linux.cpp`)**
   * `HostThreadOptions { size_t stack_reserve_bytes }`를 추가해 `HostThread` 생성 시 스택 예약 크기를 지정할 수 있게 했습니다.
   * Win32: `CreateThread`에 `STACK_SIZE_PARAM_IS_A_RESERVATION`을 전달해 가상 주소 공간만 예약하고 실제 물리 페이지는 사용 시점에 커밋되도록 했습니다.
   * Linux: `pthread_attr_setstacksize`로 스레드 스택 크기를 설정합니다(빌드 환경 제한으로 컴파일·실행 검증은 Win64에서 수행).
   * `HostThread::GetCurrentThreadStackInfo(HostStackInfo&)`로 현재 스레드의 스택 기준 주소, 예약 크기, 사용량(Win32 `VirtualQuery`, Linux `pthread_getattr_np`)을 조회합니다.
2. **스케줄러 게스트 스택 기본값 및 최고 사용량 집계 (`include/repsp/runtime/scheduler.h`, `src/runtime/scheduler.cpp`)**
   * 기본 게스트 호스트 스택 예약을 `kDefaultGuestHostStackReserveBytes = 64 * 1024 * 1024`(64 MiB)로 설정하고 `SetGuestHostStackReserveBytes` / `GetGuestHostStackReserveBytes`로 구성 가능하게 했습니다.
   * `GuestThreadInfo`에 `host_stack_reserve_bytes`, `host_stack_high_water_bytes`를 추가하고, `ThreadEntry`·`SwitchOutCurrentLocked`·`ExitThread`에서 현재 스레드의 스택 사용량을 샘플링해 최고치(`high_water`)를 갱신합니다.
   * `Scheduler::FormatHostStackStats()`로 스레드별 예약 크기와 최고 사용량 요약을 문자열로 반환합니다.
3. **프로브 추가 (`tools/kernel_sched_probe/main.cpp`)**
   * 테스트 13(`kAddrDeepStack` / `DeepStackTouch(600)`)을 추가해 2 MiB 이상 스택을 터치하는 게스트 스레드가 64 MiB 예약 내에서 정상 실행되고, `committed_bytes < 64 MiB`(reserve-only)이며 `FormatHostStackStats()`에 최고 사용량이 기록됨을 검증했습니다.

# Work Log: Guest Thread Host Stack Reserve and High-Water Reporting (repsp #32)

## Summary

Extended the platform thread creation layer and scheduler so guest threads receive an explicit large host stack without relying on a `/STACK` linker workaround, and added per-thread OS host stack high-water measurement and reporting.

## Changes

1. **Platform Thread Stack Reservation and Inspection (`include/repsp/platform/host_thread.h`, `src/platform/win32/host_thread_win32.cpp`, `src/platform/linux/host_thread_linux.cpp`)**
   * Added `HostThreadOptions { size_t stack_reserve_bytes }` to configure stack reservation when launching a `HostThread`.
   * Win32: Passes `STACK_SIZE_PARAM_IS_A_RESERVATION` to `CreateThread` so only virtual address space is reserved up front and physical pages are committed on demand.
   * Linux: Uses `pthread_attr_setstacksize` (compilation/runtime verification on Linux is pending; verified on Win64).
   * Added `HostThread::GetCurrentThreadStackInfo(HostStackInfo&)` to query stack bounds and current usage (Win32 `VirtualQuery`, Linux `pthread_getattr_np`).
2. **Scheduler Guest Stack Default and High-Water Tracking (`include/repsp/runtime/scheduler.h`, `src/runtime/scheduler.cpp`)**
   * Added `kDefaultGuestHostStackReserveBytes = 64 * 1024 * 1024` (64 MiB) with `SetGuestHostStackReserveBytes` / `GetGuestHostStackReserveBytes`.
   * Added `host_stack_reserve_bytes` and `host_stack_high_water_bytes` to `GuestThreadInfo`, sampling current usage in `ThreadEntry`, `SwitchOutCurrentLocked`, and `ExitThread`.
   * Added `Scheduler::FormatHostStackStats()` to format per-thread reserve and high-water statistics.
3. **Probe (`tools/kernel_sched_probe/main.cpp`)**
   * Added test 13 (`kAddrDeepStack` / `DeepStackTouch(600)`), verifying that a guest thread touching >2 MiB of stack completes within the 64 MiB reserve, keeps `committed_bytes < 64 MiB`, and reports its high-water in `FormatHostStackStats()`.
