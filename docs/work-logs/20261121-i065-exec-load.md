## 1. 변경 요약

1. **고정 주소 `ET_EXEC` 로더 구현 (`src/module/prx.cpp`)**
   * `ProcessPrx`가 `e_type == 0xFFA0` (PRX)와 `e_type == 2` (`ET_EXEC`)를 모두 허용하고 그 외 `e_type`은 거부하도록 확장했습니다.
   * PRX 경로는 변경하지 않았으며, `ET_EXEC` 처리를 같은 파일 내 익명 네임스페이스의 `ProcessExec` 함수로 분리했습니다.
   * `ProcessExec` 동작:
     * 모든 `PT_LOAD` 세그먼트를 검증하고 가장 낮은 `p_vaddr`을 `image_base`로 결정합니다.
     * 호출자의 `base`가 `image_base`와 다르면 두 주소를 모두 명시한 오류(`ET_EXEC is fixed at 0x...; requested base 0x...`)로 실패합니다.
     * 세그먼트는 내부 버퍼에 `vaddr - image_base` 오프셋으로 복사하고 BSS는 0으로 초기화하며, `LoadedPrx::segments`에는 링크 시점 절대 `vaddr`을 유지합니다.
     * `e_entry`가 로드된 `PT_LOAD` 세그먼트 범위 안에 있는지 검증하고 절대 주소로 반환합니다.
     * 재배치는 적용하지 않으며(`relocations_applied = 0`), `SHT_PRXRELOC`(`0x700000A0`) 또는 `SHT_PRXRELOC_COMPRESSED`(`0x700000A1`) 섹션이 존재하면 오류로 거부합니다(크기 0인 일반 `SHT_REL`은 무시).
     * `.rodata.sceModuleInfo`는 섹션 헤더가 있으면 절대 `sh_addr - image_base`로 찾고, 섹션 헤더가 없으면 첫 `PT_LOAD`의 `p_paddr`을 파일 오프셋으로 보아 `p_vaddr + (p_paddr - p_offset)`로 환산합니다.
   * `ParsePrx`의 `base`, `entry`, `gp`, `image_end`, 임포트/익스포트 테이블 해석이 `ET_EXEC`의 절대 주소와 그대로 호환됨을 확인했습니다.
2. **공개 헤더 주석 갱신 (`include/repsp/module/prx.h`, `include/repsp/runtime/prx_loader.h`)**
   * 공개 시그니처는 유지하고, PRX(`0xFFA0`)와 고정 주소 `ET_EXEC`(`2`)을 모두 지원함을 주석에 반영했습니다.
3. **합성 `ET_EXEC` 검증 추가 (`tools/prx_probe/main.cpp`)**
   * 게임 데이터 없이 코드로 생성한 합성 `ET_EXEC`(단일 `PT_LOAD` + BSS, `.rodata.sceModuleInfo`, `.lib.stub` 1개 임포트, `.lib.ent` 1개 익스포트, 빈 `.rel.text` `SHT_REL`)에 대해 `ParsePrx`, `RelocateToBuffer`, `LoadPrx`(BSS 0 초기화 포함)를 검증합니다.
   * 섹션 헤더가 없는 경우의 `p_paddr` 파일 오프셋 경로와 거부 사례(base 불일치 및 오류 메시지 두 주소 포함 여부, `SHT_PRXRELOC` 포함, `e_entry` 상한/하한 범위 이탈)를 검증합니다.
   * 기존 PRX probe 검사는 변경 없이 그대로 통과합니다(`prx_probe`는 `tools/CMakeLists.txt`의 `add_repsp_probe`로 `TIMEOUT 30` 적용).
4. **문서 갱신 (`ARCHITECTURE.md`, `docs/kb/prx-format.md`)**
   * `ARCHITECTURE.md` §2.6 모듈 로더 계약(한/영)과 `docs/kb/prx-format.md`의 PRX vs `ET_EXEC` 비교 및 `p_paddr` 규약(한/영)을 갱신했습니다.

# Work Log: Loading Fixed-Address `ET_EXEC` Executables (issue #65)

## 1. Summary of Changes

1. **Fixed-address `ET_EXEC` loader (`src/module/prx.cpp`)**
   * Extended `ProcessPrx` to accept both `e_type == 0xFFA0` (PRX) and `e_type == 2` (`ET_EXEC`) while rejecting all other ELF types.
   * Kept the PRX path untouched and placed `ET_EXEC` handling in a dedicated `ProcessExec` helper in the anonymous namespace.
   * `ProcessExec` validates `PT_LOAD` segments, computes `image_base` as the lowest `p_vaddr`, rejects base mismatches with an error naming both addresses, lays out segments at `vaddr - image_base` with zeroed BSS while preserving link-time absolute `vaddr`s in `LoadedPrx::segments`, validates absolute `e_entry` against loaded segments, rejects `SHT_PRXRELOC`/`SHT_PRXRELOC_COMPRESSED` (ignoring zero-sized ordinary `SHT_REL`), and locates `.rodata.sceModuleInfo` via absolute `sh_addr - image_base` or (without section headers) via the first `PT_LOAD`'s `p_paddr` file-offset convention `p_vaddr + (p_paddr - p_offset)`.
   * Verified that `ParsePrx` handles absolute `gp`, `ent_*`, `stub_*`, import, and export addresses without modification.
2. **Public header comments (`include/repsp/module/prx.h`, `include/repsp/runtime/prx_loader.h`)**
   * Kept all public signatures unchanged and updated comments to document `ET_EXEC` (`e_type 2`) support alongside PRX (`0xFFA0`).
3. **Synthetic `ET_EXEC` probe (`tools/prx_probe/main.cpp`)**
   * Added synthetic `ET_EXEC` tests (single `PT_LOAD` + BSS, `.rodata.sceModuleInfo`, one `.lib.stub` import, one `.lib.ent` export, empty `.rel.text` `SHT_REL`) covering `ParsePrx`, `RelocateToBuffer`, `LoadPrx` (including BSS zeroing), section-headerless `p_paddr` fallback, and rejections (base mismatch naming both addresses, `SHT_PRXRELOC`, out-of-range `e_entry` high/low).
   * All existing PRX probe checks remain unchanged and pass (`prx_probe` has `TIMEOUT 30` via `add_repsp_probe`).
4. **Documentation (`ARCHITECTURE.md`, `docs/kb/prx-format.md`)**
   * Updated `ARCHITECTURE.md` §2.6 and `docs/kb/prx-format.md` (Korean + English) with PRX vs `ET_EXEC` differences and the `p_paddr` convention.
