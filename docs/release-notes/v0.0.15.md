# repsp v0.0.15

An explicit host stack for guest threads.

Issue [#32](https://github.com/reexec/repsp/issues/32): `HostThread` takes a stack reservation (Windows: reserved only; Linux: the pthread stack size) and reports how deep the current thread's stack has ever been touched (Windows: committed pages; Linux: the deepest resident page, found starting from the previous high-water so it stays cheap). Guest threads reserve 64 MiB (configurable) instead of relying on the executable's default stack size, and each guest thread's host stack high-water is reported in the statistics. A case added to `kernel_sched_probe`. Commits `1ec657d`…`81c64cd` on task branch `i032-guest-stack`, squashed into this release's merge commit.

Background: lifted code can recurse where the guest loops. In the consumer reDMP1 one such loop ran for a whole song and overflowed the default 1 MiB stack after about 90 seconds; the consumer fixed the lifter-side cause, and since loops spanning functions remain, this reservation is the safety net.

Verified: Win64 Debug/Release and Linux x64 Debug/Release builds with CTest 21/21.
