# repsp v0.0.20

호스트 대기 중 게스트 CPU 양보, 늦은 오디오 채널 기다리기, SAS 속도, 창 없는 probe 실패.

| issue | 내용 | 커밋 |
|---|---|---|
| [#41](https://github.com/reexec/repsp/issues/41) | 다시 켜지는 짧은 SAS 보이스(리듬 게임의 키음)에 클릭과 광대역 잡음이 섞였다. 원인은 다음과 같다. 화면 표시(`sceDisplaySetFrameBuf`)가 호스트 수직동기와 GL 완료를 기다리는 동안 게스트 CPU를 쥐고 있었다. 그래서 그 사이 깨어난 높은 우선순위의 오디오 생산 스레드가 수십 ms 돌지 못했고, 짧은 채널 대기열이 비었다. 수정 내용은 아래 네 가지다. | 이 릴리스의 squash merge 커밋 |

* **`Scheduler::ScopedHostWait`**: 호스트 쪽 대기 동안 게스트 CPU를 넘긴다. 스레드는 전용 `kHostWait` 상태가 되고, 어떤 깨움·시간 초과·종료도 이 상태를 건드리지 않는다. 표시 쪽은 표시와 이벤트 처리 동안 잠금을 풀었다. 계약: 이 구간에서는 게스트 메모리, CPU 상태, 커널 객체를 건드리지 않는다.
* **오디오 믹싱 시계**: 활성 채널이 잠깐 비었을 때 무음으로 섞지 않는다. 중간 버퍼에 "장치의 최근 pull + 한 quantum"보다 많이 남아 있는 동안에는 모든 활성 채널이 한 quantum을 채울 때까지 기다린다. 평상시 지연은 늘지 않는다. 시험용 훅으로 시계를 한 단계씩 돌려 결정적으로 검사한다. `REPSP_AUDIO_DUMP`가 실제 믹스 출력(`.mix.wav`)과 언더런 위치도 기록한다.
* **SAS**: VAG 블록 읽기와 출력 쓰기를 덩어리로 한다. 출력은 바이트 단위로 같다.
* **probe**: 검사 실패는 창 없이 종료 코드 1로 끝난다(Windows Debug의 abort 창이 CTest를 멈추던 문제).

측정(한 게임, 창 모드, 같은 입력): 플레이 중 효과음 채널 언더런이 474건에서 9~14건이 됐다. 10 ms 이상 늦은 오디오 스레드 깨어남은 25~180회에서 2~3회가 됐다. 사용자가 귀로 확인했다.

검증: Win64(Visual Studio) Debug/Release, Linux x64 Debug/Release 빌드와 CTest 22/22. `audio_probe`는 Release/Debug에서 각 100회 연속 통과했다.

# repsp v0.0.20

Guest CPU yielded during host waits, late audio channels waited for, faster SAS, dialog-free probe failures.

Issue [#41](https://github.com/reexec/repsp/issues/41): short SAS voices that are re-triggered often (a rhythm game's key sounds) came out with clicks and broadband noise. The cause: presenting a frame (`sceDisplaySetFrameBuf`) waited for the host's vertical sync and GL completion while holding the guest CPU. A higher-priority audio producer woken meanwhile could not run for tens of milliseconds, and its short channel queue ran dry.

Changes:

- **`Scheduler::ScopedHostWait`** hands the guest CPU over during host-side waits.
  - The thread is in a dedicated `kHostWait` state that no wake, timeout or termination touches.
  - The display releases its lock around presentation and event polling.
  - Contract: no guest memory, CPU state or kernel object access inside the scope.
- **The audio mixing clock** no longer mixes a momentarily empty active channel as silence.
  - While the intermediate buffer holds more than the device's recent pull plus one quantum, it waits for every active channel to have a quantum. Normal latency is unchanged.
  - Test-only hooks step the clock deterministically.
  - `REPSP_AUDIO_DUMP` also writes the mixed output (`.mix.wav`) and logs underruns.
- **SAS** reads VAG blocks and writes output in bulk, with byte-identical output.
- **Probes**: a failed check exits with code 1 without a dialog. The Windows Debug abort dialog used to stall CTest.

Measured on one title, windowed, same input:

| | Before | After |
|---|---|---|
| Gameplay effect-channel underruns | 474 | 9-14 |
| Audio thread wakes 10 ms or more late | 25-180 | 2-3 |

Confirmed by ear by the user.

Verified: Win64 (Visual Studio) Debug/Release and Linux x64 Debug/Release builds pass CTest 22/22. `audio_probe` passed 100 consecutive runs each in Release and Debug.
