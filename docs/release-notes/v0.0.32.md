# repsp v0.0.32

Expired timed waits wake at safe points, so a busy lower-priority thread no longer starves a higher-priority thread whose delay has run out.

Issue [#69](https://github.com/reexec/repsp/issues/69):

- The idle path's expiry becomes `ExpireTimedWaitsLocked(now)`. `Scheduler::Poll()` now delivers interrupts, then expires timed waits, then calls `YieldIfPreempted()`.
- With no timed waiters the clock is not read.
- Priority, FIFO and preemption rules are unchanged.
- `kernel_sched_probe` checks three cases:
  - preemption when a delay expires
  - no preemption while interrupts are disabled
  - a `WaitSema` timeout
- Consumer: [reexec/reDMP2#6](https://github.com/reexec/reDMP2/issues/6).

To other consumers: scheduling gets closer to the PSP's. Timed waits that used to wake only when idle now also wake at safe points (`repsp_recomp_poll`), so higher-priority threads may run earlier.

Verified: build and CTest 23/23 on Win64 Debug/Release (zero warnings in repsp code). Linux x64 in CI.
