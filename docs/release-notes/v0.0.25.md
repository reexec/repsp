# repsp v0.0.25

Four causes of music heard later than the game clock.

- **Issue [#52](https://github.com/reexec/repsp/issues/52), blocking output**:
  - A blocking output (`sceAudioOutput*Blocking`) returned once the channel queue held at most one block, so a 1024-sample music channel always held 1.7 blocks (40.7 ms).
  - It now returns at `min(128 frames, sample_count)`. A drain still waits for empty.
  - Measured on one title: music queue 1793 → 769 frames, no mid-song underruns.
- **Issue [#53](https://github.com/reexec/repsp/issues/53), ATRAC encoder delay**:
  - The `fact` chunk's encoder delay was never skipped, so every track started that late (35-43 ms in one title). A track's last delay samples were cut, and loops restarted at a frame boundary.
  - Positions are now raw samples that include the delay. Output starts at the delay and ends at `endSample + delay`. Loops go from `loopEnd + 1` to `loopStart` within the same block.
  - The block size (`samples_per_frame`) is kept with a carry buffer.
  - The reset functions and `GetSoundSample`'s loop points use audible samples (unconfirmed on hardware).
  - The `ATRAC_TRACE` open line no longer has its arguments shifted.
- **Issue [#54](https://github.com/reexec/repsp/issues/54), GL lock**:
  - The UI thread holds `g_gl.mutex` for a whole flush. A guest thread waiting for it (GE draws, the present check) held the guest CPU meanwhile, so a higher-priority thread whose timer expired could not run. One title waited 117 ms right before its music started.
  - `LockGl()` now waits for a held lock inside a `ScopedHostWait` and retries.
  - `gl_probe` checks the handover.
- **Issue [#55](https://github.com/reexec/repsp/issues/55), start offset**:
  - `repsp::hle::atrac::SetStartOffsetMs(int32_t)` (default 0) starts newly opened tracks that much later in their content (positive, capped at the end) or after that much leading silence (negative).
  - The block size is kept, and loops and resets are not affected.
  - Apps use it to compensate host output latency against a game clock.

Confirmed by the user in windowed mode, together with the app's preemption fix and music offset.

Verified: build and CTest pass on Win64 (Visual Studio and Ninja) Debug/Release and Linux x64 Debug/Release. `audio_probe` passed 100 consecutive runs each in Release and Debug.
