# repsp v0.0.37

Models UMD replacement, and adds the HLE used on the link-disc path.

Issue [#79](https://github.com/reexec/repsp/issues/79), the UMD swap model:

- States: ejected (`0x01`) → inserted (`0x06`, `PRESENT|CHANGED`) → ready after a delay (`0x32`).
- `sceUmdReplacePermit`/`Prohibit` set a replacement-permitted flag, prohibited at start. `sceUmdCheckMedium` is added.
- State changes wake `sceUmdWaitDriveStat*` waiters.
- Host API (`include/repsp/hle/umd.h`): `IsReplacePermitted`, `GetDriveStat`, `EjectDisc`, `InsertDisc`, `SetReadyDelayMs`.
  - Inserting remounts `disc0:`/`umd0:`.
  - Calls are refused when replacement is not permitted.
- While ejected, opening or reading `disc0:`/`umd0:` fails with `0x80010013` (ENODEV).
- `umd_probe`.
- Squashed into this release's merge commit.

Issue [#80](https://github.com/reexec/repsp/issues/80), in the same commit:

- `sceUtilitySavedata` modes 12 (FILES), 13 (MAKEDATASECURE), 15 (READDATASECURE), 17 (WRITEDATASECURE), 19 (ERASESECURE), 22 (GETSIZE).
- Secure files are stored as plain files, without encryption; compatibility with hardware saves is not a goal.
- `sceIoDevctl` `ms0:` free space (`0x02425818`, clamped to 1 GiB).
- `sceKernelVolatileMemTryLock`/`Unlock` (`0x08400000`, 4 MiB).
- Checks in `iofile_probe` and `utility_probe`.

Consumer: [reexec/reDMP2#23](https://github.com/reexec/reDMP2/issues/23) (link disc). To other consumers: the UMD still starts ready, so nothing changes unless the swap API is used.

Verified: build and CTest 24/24 on Win64 Debug/Release (zero warnings in repsp code). Linux x64 in CI.
