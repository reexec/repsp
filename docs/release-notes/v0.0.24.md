# repsp v0.0.24

Screen shaders (libretro GLSL) at presentation.

Issue [#50](https://github.com/reexec/repsp/issues/50) brings over re2DJ v0.0.75's screen shaders.

- **At presentation only**: the GL helper's `DrawTexture` draws its last quad through the shader. Nothing the guest can read changes, and `none` issues the same GL calls as before.
- **Format**: a subset of libretro single-pass `.glsl` and multi-pass `.glslp`, with `#pragma parameter`. repsp's context is GL 3.3 core, so GLSL 1.20 sources are translated at assembly: the `#version` is replaced, `attribute`, `varying` and `texture2D` become macros, and `gl_FragColor` is replaced token by token.
- **Sizes**: `TextureSize` and `InputSize` are the input texture's actual pixel size. The new `LogicalSize` is the game's logical resolution.
- **Built-ins**: `crt` and `scanline` (both counting by `LogicalSize`), `fsr`, `scalefx` and `anime4k`.
- **Control**: `include/repsp/platform/post_shader.h` gives the list, `Select`, `Reload`, parameters, `SetPostShaderDirectory`, `SetInitialPostShader` and `ChoosePostShader`. A failure draws with `none` and records the reason.
- **Orientation**: a top-down CPU picture is drawn upright before a multi-pass chain, so passes reading `OrigTexture` or `PassPrevN` see it the right way up.
- `gl_probe` and `post_shader_probe` cover this.

Licenses: re2DJ (BSD 3-Clause); FSR 1.0, ScaleFX and Anime4K (MIT). See `THIRD_PARTY_NOTICES.md`.

Measured (one title):

- With `none`, input script to gameplay, three runs: mean present interval 20.30-20.47 ms, no unresolved-address dispatches.
- All five built-ins run through at a 3x window.

Confirmed by the user in windowed mode.

Verified: build and CTest pass on Win64 (Visual Studio) Release, Win64 Ninja Debug/Release and Linux x64 Debug/Release.
