# repsp v0.0.13

SAS: the loop decision at an end block corrected; audio diagnostics.

Issue [#26](https://github.com/reexec/repsp/issues/26): a SAS voice used to jump back to its start at an end block whenever the loop argument of `__sceSasSetVoice` was non-zero; it now jumps back only when the loop argument is non-zero and the block also carries the repeat flag (`0x02`) — one-shot samples that end with the end flag alone had been repeating forever. Diagnostics: `REPSP_AUDIO_DUMP` also writes one WAV per sceAudio channel and a WAV of the SAS output; `REPSP_SAS_TRACE`; `REPSP_ATRAC_TRACE`. Two cases added to `sas_probe`. Commits `4203248`…`ffeea61` on task branch `i026-sound-defects`, squashed into this release's merge commit.

Known limits (the next task): GE lists run to completion on the guest thread, so when drawing takes long the other guest threads (the one mixing sound) cannot run and sound has gaps and seems slow; this is pronounced with the software backend and mostly gone with the OpenGL backend. The underrun statistic stays at zero even when sound has gaps. The loop end point of ATRAC streams reads as an abnormal value (unresolved).

Verified: Win64 Debug/Release and Linux x64 Debug/Release builds with CTest 21/21. In the consumer reDMP1 the user confirmed by ear that sound effects no longer repeat.
