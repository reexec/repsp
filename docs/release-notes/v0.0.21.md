# repsp v0.0.21

GL texture cache: content hashes for textures in user RAM.

Issue [#43](https://github.com/reexec/repsp/issues/43): `HashGuestRange` in `gl_backend.cpp` treated any address at or above the VRAM base as VRAM. With no upper bound, it always returned 0 for user RAM addresses (`0x08000000` and up). Non-CLUT textures there were therefore cached with content hash 0, and new contents at the same address, size and format kept the old texture (one title showed the previous screen's image on the next screen).

It now checks the range with `GuestMemory::IsValidAddress` and hashes the translated bytes. `gl_probe` covers overwriting a user-RAM texture and redrawing it.

Verified: Win64 (Visual Studio) Release, and Linux x64 Debug/Release, build and CTest 22/22. Presentation intervals are in the same range as before.
