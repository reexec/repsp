# repsp v0.0.9

Rasterizer: pixel-centre sampling and the top-left fill rule for triangles.

Issue [#17](https://github.com/reexec/repsp/issues/17): the software rasterizer evaluated triangles at integer pixel corners with no fill rule, so the bottom and right edges of an axis-aligned quad (two triangles) sampled neighbouring texels; fixed by normalizing winding, testing coverage at pixel centres and applying the top-left rule on shared edges; a reproducing case added to `ge_probe`; `docs/kb/ge.md` updated. Commits `56e0e28`…`dfac497` on task branch `i017-menu-entry`, squashed into this release's merge commit.

The consumer's fault during scene teardown had its cause in the lifter, not in repsp, and was fixed on the consumer's side; repsp's HLE and scheduler are unchanged.

Verified: Win64 Debug/Release and Linux x64 Debug/Release builds with CTest 19/19.
