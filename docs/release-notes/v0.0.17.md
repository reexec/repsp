# repsp v0.0.17

Crash report: the lock holder found by boundary recovery is frozen.

Issue [#35](https://github.com/reexec/repsp/issues/35): after boundary recovery releases the scheduler mutex, another scheduler thread may take it before the report is written, so the live owner field is unreliable in that case (`crash_probe` failed on it once in CI). Recovery records the holder once, reported as `scheduler_mutex_held_at_recovery`, and `crash_probe` checks that. Squashed into this release's merge commit.

Verified: Win64 (Visual Studio) Release and Linux x64 Debug/Release builds with CTest 22/22; `crash_probe` passed 20 consecutive runs on both platforms.
