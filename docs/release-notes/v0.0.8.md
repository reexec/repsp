# repsp v0.0.8

Utility: sceUtility save data and message dialog, not drawn.

Issue [#15](https://github.com/reexec/repsp/issues/15): `repsp_hle_utility` (8 sceUtility functions: the dialog status state machine; save data modes 0-8 stored in a host directory with a real-format `PARAM.SFO` and the icon and background files; the message dialog's text recorded and answered by a consumer-set policy); path component checks on guest-supplied names; a clear stop on an unimplemented mode; the probe `utility_probe`; the knowledge base page `docs/kb/utility.md`. Commits `9abf5fd`…`c7d8032` on task branch `i015-utility`, squashed into this release's merge commit.

Known limits: dialogs are not drawn on screen (statistics show `dialog UI: not drawn`; the consumer's policy supplies the answer). Save data is stored as plaintext, so it is not compatible with saves from real hardware or other implementations.

Verified: Win64 Debug/Release and Linux x64 Debug/Release builds with CTest 19/19. In the consumer reDMP1 the real module created and loaded its save data and ran on to its title screen.
