# repsp v0.0.19

Windows: restore the stack guard outside the exception filter after an overflow, and keep stack for handlers.

Issue [#39](https://github.com/reexec/repsp/issues/39): v0.0.18 added a check that recursion past the default reservation is caught as a `Stack overflow` stop. On the Windows Release CI runner it once ended in a SegFault (not reproduced locally).

- `GuardedRun`'s exception filter called `_resetstkoflw()`. That function must not be called there, because the filter runs on the overflowed stack. It is now called in the `__except` handler, after unwinding.
- Threads with an explicit reservation (guest threads) get a 64 KiB `SetThreadStackGuarantee`, so filters and the crash handler have room after an overflow.

Verified: on Win64 Release/Debug, `kernel_sched_probe` passed 60 runs in a row and `crash_probe` 10. The Windows CI jobs were re-run repeatedly.
