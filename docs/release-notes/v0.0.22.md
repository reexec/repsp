# repsp v0.0.22

GE stall comparison on physical addresses, and cheaper GL texture hashing.

Issue [#45](https://github.com/reexec/repsp/issues/45): when a game passes uncached addresses (`0x4…`) for the list and stall, jumps inside the list go to bus addresses (`0x08…`). `list == stall` then never matched, and the GE ran past the stall into stale commands from an earlier frame (one noise frame at a title's screen transition). List pointers, stall addresses and jump/call targets are now folded to the 29-bit physical address before comparing. `ge_probe` covers this case.

Issue [#46](https://github.com/reexec/repsp/issues/46): since v0.0.21, user-RAM textures are hashed, but byte by byte over the whole texture on every draw. This starved guest threads (a title's music streaming stuttered). Changes:

- The hash now reads 8-byte words.
- A texture already hashed in the current epoch is not hashed again.
- The epoch advances at every flush, and whenever guest code may have run. The latter is signalled by the new `RenderBackend::guest_memory_may_have_changed`, which the GE interpreter calls when a list restarts after the CPU ran and after each yield.
- `gl_probe` checks the number of bytes hashed.

Measured (one title, windowed):

- The transition noise frame is gone.
- Song-select music channel underruns went from 1,981 to 68.
- The presentation interval went from 27.4 ms to 19.8 ms.

Confirmed by the user.

Verified: build and CTest pass on Win64 (Visual Studio) Debug/Release and Linux x64 Debug/Release.
