| issue | 내용 | 커밋 |
|---|---|---|
| [#21](https://github.com/reexec/repsp/issues/21) | 디코더 계약에 스트림별 문맥과 형식 확장 바이트 추가; C ABI의 플러그인 계약과 로더(`LoadCodecPlugin`; 실패하면 기본 디코더 유지); 선택적 공유 라이브러리 `repsp_codec_ffmpeg`(`REPSP_CODEC_FFMPEG=ON`일 때만 빌드; libavcodec 60 이상에 동적 링크; ATRAC3·ATRAC3plus, H.264; YUV→RGB와 float→s16 변환은 자체 구현); 사용자가 직접 실행하는 `scripts/fetch_ffmpeg.py`(고정한 LGPL 공유 빌드, SHA-256 확인, GPL 빌드 거부); platform의 동적 라이브러리 열기와 오디오 덤프 진단 `REPSP_AUDIO_DUMP`; probe `codec_loader_probe`, `codec_ffmpeg_probe`(플러그인 빌드에서만) | 작업 브랜치 `i021-codec-plugin`의 `224ede4`…`28c9736`, 이 릴리스의 squash merge 커밋 |

라이선스: 사용자 결정으로 `AGENTS.md`의 라이선스 규칙에 예외를 적었다. 선택적 플러그인에 한해 FFmpeg의 LGPL 공유 빌드에 동적으로 링크한다. FFmpeg의 소스와 바이너리는 저장소에 없고, 기본 빌드와 CI는 FFmpeg에 의존하지 않는다. FFmpeg의 구현 소스는 읽지 않았고 공개 API 헤더만 쓴다. 함께 배포할 때의 조건은 `THIRD_PARTY_NOTICES.md`에 있다.

알려진 한계: 플러그인 빌드는 Win64에서만 검증했다(Linux는 개발 패키지가 없어 빌드하지 못했다). YUV→RGB 변환(BT.601 제한 범위)이 실제 기기와 같은지는 **추정**이다. 플러그인이 없으면 종전대로 무음·검은 프레임이다.

검증: Win64 Debug/Release, Linux x64 Debug/Release 빌드와 CTest 20/20(플러그인 없는 구성), Win64 플러그인 구성 21/21. 소비자 reDMP1에서 실제 음악과 오프닝 동영상이 디코딩됐다.

# repsp v0.0.11

Codec plugin: optional ATRAC3plus and H.264 decoding through a dynamically loaded FFmpeg.

Issue [#21](https://github.com/reexec/repsp/issues/21): per-stream contexts and format extension bytes in the decoder contracts; a C ABI plugin contract and loader (`LoadCodecPlugin`; the default decoders stay on any failure); the optional shared library `repsp_codec_ffmpeg` (built only with `REPSP_CODEC_FFMPEG=ON`; dynamically linked to libavcodec 60 or later; ATRAC3, ATRAC3plus and H.264; its own YUV to RGB and float to s16 conversion); `scripts/fetch_ffmpeg.py`, run by the user (a pinned LGPL shared build, SHA-256 verification, GPL builds refused); dynamic library loading and the audio dump diagnostic `REPSP_AUDIO_DUMP` in the platform layer; the probes `codec_loader_probe` and `codec_ffmpeg_probe` (the latter in plugin builds only). Commits `224ede4`…`28c9736` on task branch `i021-codec-plugin`, squashed into this release's merge commit.

Licence: by the user's decision an exception was recorded in the licence rules of `AGENTS.md`. The optional plugin, and only it, links dynamically against an LGPL shared build of FFmpeg. FFmpeg's source and binaries are not in the repository, and the default build and CI do not depend on FFmpeg. FFmpeg's implementation source was not read; only the public API headers are used. The conditions for shipping it alongside are in `THIRD_PARTY_NOTICES.md`.

Known limits: the plugin build was verified on Win64 only (on Linux it could not be built for lack of the development packages). Whether the YUV to RGB conversion (BT.601 limited range) matches the real device is **assumed**. Without the plugin decoding is silent and black as before.

Verified: Win64 Debug/Release and Linux x64 Debug/Release builds with CTest 20/20 (the configuration without the plugin), and 21/21 in the Win64 plugin configuration. In the consumer reDMP1 real music and the opening movie were decoded.
