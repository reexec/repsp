오디오 끊김: GE 리스트 실행 중 선점 지점, 호스트 쪽 오디오 버퍼.

| issue | 내용 | 커밋 |
|---|---|---|
| [#28](https://github.com/reexec/repsp/issues/28) | GE 인터프리터가 리스트 실행 중 주기적으로(큰 primitive는 나눠서) 양보 콜백을 부르고, `repsp_hle_ge`가 이를 스케줄러의 선점 확인에 연결(우선순위가 더 높은 준비 스레드가 있을 때만 양보; 실행 중 재진입 보호); `repsp_hle_audio`에 호스트 쪽 중간 버퍼(믹싱 스레드가 128프레임 단위로 게스트 채널에서 끌어와 쌓고 장치는 거기서 끌어감; 목표 지연 `target_latency_ms` 기본 20 ms, `REPSP_AUDIO_LATENCY_MS`); 실제 underrun·모자란 프레임·버퍼 깊이·끌어가기 단위 통계; 스케줄러의 wake latency 계측(`REPSP_SCHED_STATS`); GE 리스트 실행 시간 통계; `ge_probe`·`audio_probe`에 경우 추가 | 작업 브랜치 `i028-audio-gaps`의 `b7f33dd`…`b3446d9`, 이 릴리스의 squash merge 커밋 |

스케줄러의 선점 규칙과 게스트가 보는 오디오 출력 대기의 의미는 바뀌지 않았다. 선점 지점이 늘었고, 장치와 게스트 큐 사이에 버퍼가 생겼다.

알려진 한계: HLE 호출 없이 오래 도는 게스트 코드(로딩 등)는 여전히 선점되지 않아 그동안 소리가 빈다(측정만 했다). 소프트웨어 백엔드에서는 끊김이 줄었지만 남는다. 중간 버퍼만큼 소리가 늦게 난다(기본 20 ms).

검증: Win64 Debug/Release, Linux x64 Debug/Release 빌드와 CTest 21/21. 소비자 reDMP1에서 OpenGL 백엔드의 장치 출력에 짧은 무음이 0건이었고, 사용자가 귀로 개선을 확인했다.

# repsp v0.0.14

Audio gaps: preemption points while a GE list runs, and a host-side audio buffer.

Issue [#28](https://github.com/reexec/repsp/issues/28): the GE interpreter calls a yield callback periodically while a list runs (splitting large primitives), and `repsp_hle_ge` connects it to the scheduler's preemption check (yielding only when a higher-priority thread is ready; re-entry guarded while a list runs); `repsp_hle_audio` gains a host-side intermediate buffer (a mixing thread pulls from the guest channels in 128-frame steps and the device pulls from the buffer; target latency `target_latency_ms`, default 20 ms, `REPSP_AUDIO_LATENCY_MS`); statistics for real underruns, shortfall frames, buffer depth and pull sizes; wake latency profiling in the scheduler (`REPSP_SCHED_STATS`); GE list run time statistics; cases added to `ge_probe` and `audio_probe`. Commits `b7f33dd`…`b3446d9` on task branch `i028-audio-gaps`, squashed into this release's merge commit.

The scheduler's preemption rule and what the guest sees of blocking audio output are unchanged: there are more preemption points, and a buffer now sits between the device and the guest queues.

Known limits: guest code that runs long without an HLE call (loading, for instance) is still not preempted, and sound has a gap meanwhile (measured only). With the software backend the gaps are fewer but remain. Sound is delayed by the intermediate buffer (20 ms by default).

Verified: Win64 Debug/Release and Linux x64 Debug/Release builds with CTest 21/21. In the consumer reDMP1 the device output with the OpenGL backend had zero short silences, and the user confirmed the improvement by ear.
