# repsp v0.0.3

Kernel HLE: the scheduler, kernel objects and the first firmware modules.

Issue [#5](https://github.com/reexec/repsp/issues/5): in runtime, a single-core fixed-priority scheduler (a baton; a preempted thread stays at the front of its priority; deadlock reports), the kernel object table, system time, `Vfs` (device mapping, path normalization, case-insensitive lookup) and the user partition; `repsp_hle_kernel` with ThreadMan (threads, signal/set-time handoff wait queues for semas and event flags, callbacks), SysMem, IoFileMgr (including async), ModuleMgr (disc PRX as HLE modules), LoadExec, Utils, Stdio, Kernel_Library, power and suspend, and UMD — 65 functions; `KernelConfig`; `REPSP_HLE_TRACE`; the probes `kernel_sched_probe`, `sysmem_probe`, `iofile_probe` and the 65-NID table. Commits `ae849d2`…`e5bb123` on task branch `i005-kernel-hle`, squashed into this release's merge commit.

Verified: Win64 Debug/Release and Linux x64 Debug/Release builds with CTest 9/9. In the consumer reDMP1 the real module booted from `module_start` to its first non-kernel call deterministically (the same trace three times).
